# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Multi-Bot** — a Bulgarian-language **teaching project**: a multi-agent SDLC system (Supervisor + Analyst + Developer + QA) built on LangChain 1.x + LangGraph 1.x. "Multi-Bot" is the system's name; use it in all user-facing titles and docs. Code comments and docstrings are in Bulgarian and deliberately verbose/explanatory — keep that style when editing (tests included). The linter is ruff (`ruff.toml`), configured to tolerate that style (E501 ignored — long Bulgarian comments/prompts are fine).

**Tests:** `tests/` is a pytest suite covering the whole workflow with **zero real LLM calls and no disk writes outside `tmp_path`** — triage decisions, plans, QA verdicts and workers are scripted test doubles (see `tests/conftest.py`: `FakeLLMFactory` dispatches by Pydantic schema, `FakeWorkerAgent` accepts `context=` and an optional `side_effect` that simulates tool work such as marking a plan step done). Four layers: unit (tools/i18n/config/modes/plans/run_tracker/step_plans/dod/hitl/toolsets/graph building blocks), integration (real `create_agent` agents + real tools driven by a fake tool-calling model, incl. `update_plan_step` through `ToolRuntime`), E2E (the real graph: happy path, rework loop + limit, DoD retry/escalation, triage entries, on-disk artifacts, HITL gates via `InMemorySaver` + `Command(resume=...)`, streaming contract incl. `__interrupt__`, bilingual reasons), and **evals** (`tests/evals/`, marker `eval`, golden YAML cases + LLM-as-judge through `get_llm()` — real LLM costs, excluded by default via `pytest.ini` `-m "not eval"`, run explicitly with `pytest -m eval`; they build the graph with `mode="demo"`). The autouse `_clean_env` fixture forces `APP_MODE=demo`, `HITL_GATES=""` (no gates), `RUNS_DIR`/`WORKSPACE_DIR` under `tmp_path` and clears `APP_LANG`/`MAX_REWORK`/HITL/Jira vars so every test starts at defaults; `scripted_graph(hitl_gates=("plan",))` turns gates on for a test. Helper names in conftest must not start with `test_`/`Test` (pytest collects them) — hence `sample_plan()`/`sample_test_plan()` and `plans_module.TestPlan`. Lint: `ruff check .` (config `ruff.toml`); CI (`.github/workflows/ci.yml`) gates PRs on ruff + pytest + 85% coverage of `src/`. Run: `.\.venv\Scripts\python.exe -m pytest`. When changing graph/agents/tools behavior, keep the suite green and extend it.

**Bilingual (bg/en):** all user-facing strings live in `src/i18n.py` (`t("key")`, language from `APP_LANG` env, `bg` default) — never add user-facing literals directly in `main.py`/`app.py`; add a key to `STRINGS` with **both** languages (import-time validation fails on half-translated keys). Agent prompts (`agents.py`, `graph.py`) and mock tool data (`tools.py`) are per-language dicts. Prompts are fixed at `build_graph()` time (language is part of the Streamlit graph cache key); tool texts resolve at call time. Docs are mirrored: `README.md` (bg) ↔ `README.en.md` (en) — edits to one must be mirrored in the other. Code comments stay Bulgarian-only by design.

## Branching workflow (enforced by hooks)

**`main` is production.** Never commit or push to it directly — `.githooks/pre-commit` blocks commits on main and `.githooks/pre-push` blocks pushes to main. All work goes on a `feature/<name>` branch, pushed, then merged via PR (`gh pr create --fill` → `gh pr merge --squash --delete-branch`). Emergency escape hatches: `SKIP_MAIN_GUARD=1` or `--no-verify`.

Release notes live in `CHANGELOG.md` (Keep a Changelog format, Bulgarian). Completed user-facing functionality gets an entry under `[Unreleased]` — the pre-push hook adds these automatically; on release, entries move under a version number.

## Git hooks

`.githooks/pre-push` also runs `claude -p` (headless) before every push to check whether the commits being pushed made CLAUDE.md / README.md / README.en.md / requirements.txt / CHANGELOG.md inaccurate, that the two READMEs stay mirrored, and that new user-facing strings have both bg+en versions in `src/i18n.py`. If so, it creates a separate `docs-sync:` commit and **aborts the push with exit 1** — the user re-runs `git push`, which passes immediately (a `docs-sync:` HEAD skips the check). Opt-in via `git config core.hooksPath .githooks`. Skip with `git push --no-verify` (all hooks) or `SKIP_DOCS_UPDATE=1 git push` (docs sync only). It also no-ops when the pushed commits touch only the doc files, when the doc files have uncommitted changes (never commits someone's WIP), and guards against nested invocation via `CLAUDE_DOCS_HOOK_RUNNING`.

## Architecture

Supervisor pattern on one LangGraph `StateGraph`, productionized per `improvement.md` and extended per `docs/prod-mode-plan.md`: the LLM decides **only** what code cannot. Topology: `START → init_run → supervisor → analyst → dev_plan → approve_plan → developer → qa_plan → qa → approve_publish → finalize → END` (`PIPELINE` in `src/graph.py`; `escalation_gate` sits between any escalation and `finalize`). `init_run` (pure code) creates `runs/<YYYY-MM-DD_HH-MM-SS>_<TICKET>/` and extracts the ticket key. `supervisor` (Pydantic `SupervisorDecision`) does a **one-time triage** — entry point or FINISH — mapped through `ENTRY_NODE` (`developer → dev_plan`, `qa → qa_plan`, `FINISH → finalize`) so a plan always precedes work. `dev_plan`/`qa_plan` make **one structured LLM call each** (`ImplementationPlan`/`TestPlan` in `src/plans.py`); the plan JSON is the source of truth, markdown with checkboxes is re-rendered (never regex-edited); agents report progress with the `update_plan_step`/`update_test_case` tools, which get the run directory through `ToolRuntime[RunCtx]` (`src/run_context.py`, passed as `agent.invoke(..., context=)`). Everything else is deterministic code over typed state artifacts (`TeamState`: `spec`, `plan`, `code`, `test_plan`, `qa_verdict`, `rework_count`, `dod_retries`, `final_status`, `run_id`/`run_dir`/`mode`, `hitl_decisions`, `plan_revisions`, `retry_target`, `publish_status`), each phase gated by a code-checked Definition of Done (`src/dod.py`: `DemoDoD` = ```python block + `ast.parse`; `ProdDoD` = non-empty diff + parsable .py + ≥1 step done — real workspace lands in PR 3). A missed DoD → **one** self-retry with the concrete problem injected, then `next="escalation_gate"` with `final_status="ESCALATED"`. QA's ReAct report is distilled into a structured `QAVerdict`; routing reads the verdict: APPROVED → `approve_publish` → `finalize`, NEEDS_WORK → developer (the plan gets a "Rework N" section, the test plan is reset; **no re-planning**) up to `MAX_REWORK` times, then `escalation_gate`. Every node writes `next`+`reason`; one shared `route_next` conditional edge reads it; only `finalize` writes `next="FINISH"` and it always writes `summary.json` + `traceability.md`.

**Human-in-the-Loop** (`src/hitl.py`): gates are separate nodes built by `make_gate_node` around LangGraph `interrupt()`; `HITL_GATES` env (unset → `default_gates(mode)`: prod `plan,publish,escalation`, demo `plan,escalation`; empty string → none), `HITL_MAX_REVISIONS` (2), `HITL_AUTO_APPROVE=1` (non-interactive). Decisions are `{"action": approve|revise|abort, "feedback", "by"}` (or shortcuts `a`/`r: text`/`q`; invalid → abort). `approve_plan`: revise → back to `dev_plan` with the feedback as a `HumanMessage`; `escalation_gate`: approve/revise both mean *retry* the `retry_target` node with counters reset, abort keeps ESCALATED; a disabled gate is pass-through with reason `route_gate_auto` and records **no** decision (only real/auto decisions go to `hitl_decisions` + `hitl-decisions.md`). Gates need a checkpointer: `build_graph()` falls back to `InMemorySaver` when gates are on and none is given, so main.py/app.py must always pass a `thread_id` (uuid per run when there is no SQLite path). Consumers resume with `graph.stream(Command(resume=decision), config)` and must handle the `{"__interrupt__": (Interrupt,)}` step in the stream.

**Modes** (`src/modes.py`, `src/toolsets.py`): `APP_MODE=prod|demo` (default **prod**; invalid → `ValueError`), read in `build_graph(mode=..., repos=...)`; `make_mode_context(mode, repos)` returns `DemoContext` or a `ProdContext` (Jira client + `jira_tools`, one `RepoWorkspace` per selected repo, a `MultiWorkspace` view for `ProdDoD`, repo read/write/diff tools, a `Publisher`, and `prepare_workspaces(ticket_key, run_id)` which `init_run` calls) — prod modules are lazy-imported so `import src.graph` needs no `mcp` package or keys (a static AST test guards it). Constructing the prod context touches no network; only `prepare_workspaces` (clone/fetch) and `Publisher.publish` (push, `gh`) do. `make_tools(mode, ctx)` gives each role its tools + a per-mode `prompt_addendum` appended to the base prompt; tool names shared by both modes must keep identical name/args/description (`get_ticket_details` — the prod tool copies the demo tool's `description`; a contract test enforces it). A `ProdContext` without repo tools (e.g. a bare `ProdContext()` in tests) falls back to the demo delivery addenda and `DemoDoD`. `validate_prod_config(mode, selected_repos)` returns human-readable problems (missing `PROD_REPOS`/Jira vars, nothing selected) — the UI disables Run on them. Workers are `create_agent` ReAct agents; demo tools (`src/tools.py`: fake Jira, coding standards, `ast.parse` syntax check — code is never executed) plus the plan tools.

**Git workspace + publishing** (`src/repo_workspace.py`, `src/publish.py`): plain `subprocess` git through an injectable `runner` (no GitPython); `RepoWorkspace.prepare()` clones (`core.autocrlf=false`) or fetches into `WORKSPACE_DIR/<owner>__<name>`, `start_run(branch)` = `checkout -B <branch> origin/<base>` + `reset --hard` + `clean -fdx` (every run starts pristine; branch = `branch_name(ticket_key, run_id)` → `multibot/<key>-<run tail>`). `_resolve()` is the security boundary for LLM-supplied paths: no empty/absolute/UNC paths, no `..`/`.git` components, no symlinks, `DENY_GLOBS` for secrets, size cap, binary refusal — every `WorkspaceError` becomes tool text. `diff()`/`changed_files()` stage first (`git add -A` → `--cached`) so new files count; `changed_files()` uses `--diff-filter=ACMR`, so deletions don't satisfy the DoD. `MultiWorkspace` prefixes paths as `owner/name:path`. `Publisher.publish(state, tracker)` never raises: per repo with `has_changes()` → commit (author from `PROD_GIT_AUTHOR_*`) → push → `pr-body-<slug>.md` → `gh pr create --draft` (an "already exists" answer falls back to `gh pr view`); result = `publish_status` `PUBLISHED|PUBLISH_FAILED|SKIPPED` (+ `SKIPPED_BY_HUMAN` set by the gate), `pr_urls`, `publish_errors`, `reason`; the Jira comment (`JIRA_WRITE_BACK=1`) is best-effort and only adds an error. `finalize` only publishes when `mode == "prod"` and `final_status == "APPROVED"`; `approve_publish` shows the diff (```diff fence), the QA verdict, the test plan and the PR body preview. Tests: `bare_repo` fixture (`git init --bare -b main` + seed clone/push), `FakeGhRunner` (real git, simulated `gh`), `fake_jira_client`, and `prod_context` which patches `graph_module.make_mode_context` so `scripted_graph(mode="prod")` runs the real graph over a real local repo; `_clean_env` sets `GIT_CONFIG_NOSYSTEM/GIT_CONFIG_GLOBAL/GIT_TERMINAL_PROMPT` so developer git config (signing, hooks) never leaks in.

**Jira via MCP** (`src/jira_mcp.py`): the official Atlassian Remote MCP Server (`https://mcp.atlassian.com/v1/mcp`) through the official `mcp` Python SDK (pinned `mcp==1.29.1`), not `langchain-mcp-adapters`. `JiraMcpSettings.from_env()` (`JIRA_MCP_AUTH=api_token|oauth`, `JIRA_EMAIL`/`JIRA_API_TOKEN` → `Authorization: Basic base64(email:token)`, `JIRA_CLOUD_ID` = site hostname, `JIRA_MCP_COMMAND` for the `mcp-remote` stdio variant, timeout/retries, `JIRA_AC_FIELD`, `JIRA_WRITE_BACK`). One MCP session per call (`_call_over_mcp`: connect → `initialize` → `call_tool`), run through `_run_sync` = a dedicated thread + `asyncio.run` (works from the CLI and from Streamlit's loop). Verified live response shapes: results are JSON text in the first `TextContent` block; with `responseContentFormat: "markdown"` `fields.description` is plain text (ADF fallback `adf_to_text` kept anyway); `searchJiraIssuesUsingJql` returns `{"issues": {"nodes": [...]}}`; errors are `{"error": true, "message": ...}` (→ `JiraMcpError`, never retried); unbounded JQL is rejected (the `search_tickets` docstring and error hint tell the model to bound it). Transport errors are retried with backoff (`sleep` injectable); `ImportError` (no `mcp`) is not retried. `JiraMcpClient(settings, call_tool=...)` is the test seam — tests use a fake `call_tool` with fixtures in the verified shape, zero network.

**Run tracing** (`src/run_tracker.py`, `src/step_plans.py`): every node is wrapped by `_traced` in `build_graph()` (node factories stay pure for unit tests). Before the node: `steps/NN-<node>.md` with a "План" section from a per-node template; after: "Изпълнение" (result, artifacts, DoD, next/reason), `run.jsonl` event (deduped by `(seq, node)`), phase artifacts (`spec.md`, `code.py|code.diff`, `qa-report.md`), `index.md`, `STATUS.md`. `step_seq` in state gives deterministic numbering so resume/interrupt re-execution overwrites instead of duplicating. All writes are atomic (`tmp` + `os.replace`, with a PermissionError retry for Windows AV locks). `RunTracker.from_state()` returns a `NullTracker` when there is no `run_dir` (unit tests of node factories). main.py/app.py add what the graph cannot know: `write_usage()` (tokens/cost) after the stream.

Resilience/cost knobs (all env, read per call): per-role models `MODEL_SUPERVISOR`/`MODEL_ANALYST`/`MODEL_DEVELOPER`/`MODEL_QA` (fallback `MODEL_NAME`; Ollama analog `OLLAMA_MODEL_<ROLE>`), `LLM_MAX_RETRIES` (3) and `LLM_TIMEOUT_SECONDS` (120) on the Anthropic client, `MODEL_FALLBACK`/`OLLAMA_MODEL_FALLBACK` (empty=off) — a second-model fallback chain built by `make_structured_llm()` in `src/graph.py` for the two structured decisions only (triage + QA verdict; ReAct agents rely on client retries), `MAX_COST_USD_PER_RUN` (0=off) — checked by main.py/app.py between stream events via `budget_exceeded()` in `src/config.py`, and `CHECKPOINT_SQLITE_PATH` (empty=off) — `get_checkpointer()` builds a `SqliteSaver`, `build_graph(checkpointer=...)` compiles with it, main.py/app.py then pass `thread_id` (env `THREAD_ID` or sha1 of the task) so an interrupted run resumes on the same thread.

GitHub `main` also has server-side branch protection: the CI check `test` is required and force-pushes/deletions are blocked (set via `gh api .../branches/main/protection`).

- `src/config.py` — `get_llm()` factory. Reads `LLM_PROVIDER` from env **on every call**: `anthropic` (default, `claude-opus-5`) or `ollama` (local `qwen3:8b`, fully offline). Also holds `MODEL_PRICES_USD_PER_MTOK` + `estimate_cost_usd()` for the cost report.
- `src/graph.py` — the graph. Contract to preserve: all LLM-dependent and external objects (agents, structured LLMs, mode context, tools) are created **inside** `build_graph()`, not at module level — this is what lets the UI switch providers/modes at runtime and lets the module import without any API key (a test guards this, incl. `make_tools`/`make_mode_context`). Don't hoist them out. `max_rework` lives in `src/modes.py` and `extract_python_code` in `src/dod.py` (both re-exported from `graph.py`).
- `main.py` / `app.py` — visualization only; the graph itself never prints (it only writes files under `RUNS_DIR`). Both stream with `stream_mode="updates", subgraphs=True` (subgraphs=True exposes the workers' inner tool calls) and attach a `UsageMetadataCallbackHandler` for the token/cost summary (it also captures the supervisor's calls, which never appear in the stream). Both loop over the stream until no `__interrupt__` arrives: main.py asks on stdin (`ask_human`, no TTY → `HITL_AUTO_APPROVE` or abort), app.py keeps the whole run (`config`, counters, `usage_cb`, `pending_input`, `pending_gate`) in `st.session_state.run` so the HITL panel survives reruns and continues with `Command(resume=...)` on a button click. Streamlit's graph cache key is `(provider, lang, mode, gates)`.
- `docs/prod-mode-plan.md` is the living plan for the Demo/Prod work (checkboxes in §9 are ticked per PR); before each implementation step a dated plan goes to `docs/plans/<YYYY-MM-DD_HH-MM>_<step>.md` and is annotated with what was done — the same "plan before / record after" discipline the agents follow.
- A real demo run with Opus 5 costs ~$4–5 when QA is strict (two rework cycles); `MAX_COST_USD_PER_RUN` stops it cleanly (the consumer writes `final_status=BUDGET_EXCEEDED` into `run.jsonl`, `finalize` does not run, so no `summary.json` final status).

## Gotchas (each one cost a debugging session)

- **Thinking blocks:** Opus 5 returns content as a list of blocks (thinking + text). Worker results are re-injected as `HumanMessage`s, and the API rejects thinking blocks in non-assistant messages — always route agent output through `extract_text()` (`src/graph.py`).
- **No LangSmith / LangGraph Studio.** The project deliberately has no external tracing/observability dependency — everything runs locally (Streamlit UI for live visualization, `draw_graph.py` for the graph diagram). The `langsmith` package remains only as a transitive dependency of langchain-core; never enable `LANGSMITH_TRACING` or add Studio configs back.
- **Ollama models must support tool calling** (qwen3, llama3.1). The locally available BgGPT is Gemma-2-based and does not — agents' tools and the supervisor's structured output fail on it.
- **Console encoding:** `main.py` calls `sys.stdout.reconfigure(encoding="utf-8")` — without it Cyrillic breaks when output is redirected on Windows.
- **Streamlit reruns wipe output:** `app.py` stores every graph event in `st.session_state.events` and replays them on rerun. New UI output must go through `emit()`/`render_event()`, not bare `st.*` calls inside the run loop.
- Streamlit can inherit `LLM_PROVIDER` from the launching shell; `load_dotenv()` does not override it. `app.py` reads the sidebar default from `dotenv_values()` for this reason (same for `APP_MODE` and `HITL_GATES`).
- **Bash heredocs in this environment mangle backslashes/quotes** in multi-line Python — write patch scripts to a file and run them instead of `python - <<'EOF'`.
- **Windows `os.replace` can raise `PermissionError`** right after writing a file (AV/indexer lock) — `run_tracker._atomic_write` retries; don't rewrite every step file on every step (only the changed one + `index.md`).
- **pytest collects anything named `test_*`/`Test*` imported into a test module** — conftest helpers are `sample_plan()`/`sample_test_plan()` and the schemas are referenced as `plans_module.TestPlan`.
- **`interrupt()` inside a `_traced` node**: the wrapper lets `GraphInterrupt` propagate (marking the step WAITING in `STATUS.md`); on resume the whole node re-runs with the same `step_seq`, so everything the wrapper writes must be idempotent.
